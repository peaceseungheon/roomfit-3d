# 다중 방 평면도 — 설계

작성일 2026-11-19 · 상태: 승인 대기 · 근거 우선순위: `docs/PRD.md` > 이 문서 > `docs/기획서.md`

## 1. 의도와 이유

평면도는 보통 방이 여러 개로 이루어진 집 한 채다. 가구는 방 하나가 아니라 집 전체를 놓고 배치한다.
지금은 문서가 방 1개(`room`)만 담을 수 있어서, 평면도를 완전하게 재현할 수 없다.
**목표: 한 문서에 방 여러 개를 두어 집 한 채의 평면도를 정확하고 편하게 재현하고, 그 위에 가구를 배치·검증한다.**

## 2. 목표 / 비목표 / 안티골

**목표**
- G1. 한 문서에 방 N개(상한 20). 방마다 이름·천장고·다각형.
- G2. 한 장의 평면도 이미지에서 축척을 한 번만 잡고 방을 차례로 따서 방끼리 위치가 어긋나지 않게 한다.
- G3. 이웃 방의 꼭짓점·변에 달라붙는 스냅으로 방 사이 간격을 일정하게 맞춘다.
- G4. 가구·문·창을 모든 방 기준으로 배치하고 충돌·벽 경고를 계산한다.
- G5. 기존 `1.0` 저장 파일과 자동 저장 데이터는 방 1개짜리 문서로 그대로 불러온다.

**비목표**
- 바깥 윤곽 + 칸막이 벽 모델(승인 전 비교 시 B안), 변 공유 위상 모델(C안).
- 층 여러 개, 방별 바닥 재질, 벽 두께를 방마다 다르게 하기, 벽 개구부(문 모양으로 벽을 뚫기).
- 평면도 이미지에서 방을 자동으로 여러 개 분할하기(AI 분석은 v1.1 이후).

**안티골**
- 방 하나만 쓰는 사용자가 이전보다 클릭이 늘어나거나 기존 화면이 달라지면 실패다.
- 방 내부 바닥이 겹치는 문서가 저장·불러오기를 통과하면 실패다.

## 3. 제약

- 단위 1unit=1cm, 좌표 [x, z], 10cm 스냅(`roomfit-conventions`). 불변 갱신(스프레드), 파일 800줄 이하.
- 방 하나의 가로·세로 상한 3000cm(`ROOM_MAX`), 꼭짓점 3~100개는 방마다 그대로 적용한다.
- Undo/Redo 대상은 `{rooms, items}`. 활성 방 선택은 Undo 대상이 아니다.

## 4. 접근 방식

| 안 | 요약 | 결과 |
|---|---|---|
| **A. 방 다각형 여러 개 (선택)** | `rooms: Room[]`을 같은 전역 좌표에 배치. 방마다 기존 생성·트레이싱·그리기·홈/돌출 재사용 | 채택. 사용자가 "방을 여러 개 만든다"로 생각하고 코드 재사용이 가장 큼 |
| B. 바깥 윤곽 + 칸막이 벽 | 방은 벽에서 자동 계산 | 방 생성 흐름 전체 재작성. 제외 |
| C. 변을 공유하는 방 다각형 | 인접 방이 변 공유, 벽·개구부는 변 단위 | 변 공유 유지 로직이 복잡. 제외 |

## 5. 결정 사항 (사용자 승인: A안)

### 5.1 데이터 모델
- `Room`에 `id: string`, `name: string` 추가. `DocData = { rooms: Room[]; items: Item[] }`.
- 저장 JSON `version: "1.1"`, 최상위 `rooms: Room[]`(1개 이상 20개 이하). 쓰기는 항상 1.1.
- 읽기는 `1.0`(`room` 1개)과 `1.1`을 모두 받는다. `1.0`은 `{id:'r1', name:'방 1', ...room}`으로 감싼다. 둘 다 아니면 오류 경로를 포함해 거부한다.
- 가구·고정 요소(`Item`)는 지금처럼 **전역 좌표**를 쓴다. 소속 방은 저장하지 않고 위치로 판정한다.
- 방 id는 중복 불가. 방 이름은 1~`NAME_MAX`자.

### 5.2 방 배치 규칙 (내부 치수 + 벽 간격 모델)
- 방 다각형은 **벽 안쪽 면(내부 치수)**이다. 지금 `Scene`이 `offsetOutward(points, WALL_THICKNESS)`로 바깥쪽에 벽을 쌓는 방식을 그대로 방마다 쓴다.
- 방 사이 간격은 **0 이상이면 모두 허용**한다. 평면도에서 방 내부 윤곽을 따면 벽 두께만큼 간격이 자연히 생기고, 간격 0은 벽 없이 이어진 열린 구조(거실+주방 등)로 쓴다.
- 벽 렌더 규칙: 각 방의 벽 링(`WALL_THICKNESS`=10cm)에서 **모든 방의 내부 영역을 뺀다**. 그러면 간격 0이면 벽이 없고, 0 초과 20cm 이하이면 두 링이 겹쳐 간격 전체가 채워져 하나로 보이고, 20cm 초과이면 가운데에 빈 틈이 남는다(허용, 경고 없음).
- 검증 오류는 **내부 면적이 겹칠 때만**이다. 변이 맞닿거나 한 점이 닿는 것은 오류가 아니다(경로 `rooms[i]`).
- 문서 전체 바운딩 박스 상한은 10000cm(내 판단, 3000cm 방 3~4개 가로 배치 허용). 방 개수 상한 20은 UI에서 추가 버튼을 비활성화하고 이유를 표시하며, 불러오기·확정 시에는 오류로 거부한다.
- **좌표 불변식:** 문서 전체에서 모든 방 꼭짓점의 최소 x, 최소 z는 0 이상이다(음수 좌표 없음). 이 불변식은 새 방을 확정할 때 문서 전체(모든 방 + 모든 가구)를 같은 양만큼 옮겨 유지하며, 그 옮김은 방 추가와 같은 Undo 1단계다(`shiftItems` 재사용).

### 5.3 판정 규칙 (충돌·벽·고정 요소)
- 가구 바닥 박스가 **어느 한 방 안에 온전히** 있으면 벽 경고 없음. 방 사이에 걸치거나 모든 방 밖이면 `WALL` 경고(기존 `insideRoom`을 방별로 호출).
- **소속 방 정의(가구):** 바닥 박스 **중심점**이 내부에 있는 방. 어느 방에도 없으면 소속 없음. 소속은 천장고 clamp와 방 이동 시 동반 이동에만 쓴다. 소속 없는 가구는 이동하지 않고, clamp는 가장 낮은 천장고를 쓴다.
- **소속 방 정의(문·창):** 호스트 벽이 속한 방.
- 문·창의 호스트 벽은 **모든 방의 모든 변 중 가장 가까운 변**으로 정한다. 거리가 같으면(1cm 이내) 방 배열 앞쪽 방을 택한다(결정적 규칙). `nearestWall`을 방 인덱스까지 돌려주는 다중 방 버전으로 일반화하고, 호스트 방의 `points`로 문 열림 부채꼴·`NO_SPACE`를 계산한다. 문을 옮겨 호스트 방이 바뀌면 안/바깥 방향은 새 호스트 방 기준으로 매번 다시 계산한다.
- 문 열림 부채꼴이 다른 방의 가구와 겹치면 기존 `DOOR_SWING` 경고가 그대로 적용된다(가구는 전역 목록).
- 천장고는 방마다 다르다. `elevation` clamp는 가구의 소속 방 기준.

### 5.4 활성 방과 UI
- `useUiStore.activeRoomId`(Undo 비대상). 바닥을 클릭하거나 방 목록에서 선택한다. 모서리 편집 핸들·`WallEditor`·`RoomDialog`·치수 패널의 방 편집은 활성 방에만 적용한다.
- 우측 패널에 방 목록 섹션: 이름 변경, 삭제, 방 추가 버튼. 방이 1개일 때 목록은 접힌 한 줄로 두어 기존 화면과 같게 둔다.
- 방 삭제 시 확인 대화상자. 그 방 안의 가구는 삭제하지 않고 남기며, 방 밖이라 `WALL` 경고가 뜬다.
- 방 추가 방법 3가지: 사각형·ㄱ자(활성 방 오른쪽에 간격을 두고 배치), 트레이싱, 빈 캔버스 그리기. 트레이싱·그리기는 아래 5.5 흐름을 쓴다.

### 5.5 트레이싱·그리기 다중 방
- 트레이싱 화면은 이미지·축척·기준선을 방을 만든 뒤에도 **세션 메모리(`useTraceStore`)에만** 유지한다. 저장 JSON에는 넣지 않는다. "이 방 확정" 후 "다음 방 따기"로 같은 이미지에서 새 다각형 작업을 시작한다.
- **좌표 연속성:** `toRoomPoints`는 지금 방의 최소 좌표를 (0,0)으로 옮긴다. 다중 방에서는 트레이싱 세션이 "이미지 좌표 → 문서 좌표" 오프셋을 보관하고, 첫 방 확정 때 생긴 이동량과 이후 5.2의 문서 전체 이동량을 누적한다. 두 번째 방부터는 이 누적 오프셋을 적용해 첫 방과의 상대 위치를 유지한다(방 개별 정규화 없음).
- **진입점:** 새 문서(전체 교체, 기존 "가구 유지" 선택 유지)와 방 추가(기존 방·가구 보존)를 방 대화상자에서 구분한다. 방 확정 1회는 Undo 1단계이고, 트레이싱·그리기 중간 상태는 Undo 대상이 아니다(현재와 같음).
- 이미 확정된 방은 트레이싱 캔버스에 옅은 윤곽으로 표시한다.
- **스냅:** 그리는 점이 이웃 방의 꼭짓점 또는 변에서 `SNAP_RADIUS`(기본 15cm) 안이면 달라붙는다. 변 스냅은 이웃 변과 `WALL_THICKNESS × 2` 간격이 되는 평행선에 투영한다. 스냅 해제 키를 둔다.
- 확정 전 검증에 "다른 방과 내부가 겹침"을 추가한다(`closePolygon` 오류 목록 확장).
- 모서리 편집(점 이동·삽입·삭제)에서도 같은 겹침 검증을 쓴다.
- 홈/돌출(`notchWall`)은 활성 방에만 적용한다. 정규화로 활성 방이 옮겨지면 그 방 소속 가구(5.3의 중심점 기준)만 같이 옮기고, 그 방의 이동이 불변식(5.2)을 깨면 문서 전체를 옮긴다. 사용자가 방을 직접 끌어 옮기는 기능은 이번 범위에 없다.

### 5.6 장면·카메라
- 벽·바닥은 방마다 렌더(`Scene`의 단일 `room` 사용 제거). 치수 라벨은 활성 방에서 강조, 나머지는 옅게.
- 카메라 범위(`CameraRig`)와 가구 초기 배치 위치(`placement.ts`)는 모든 방의 합집합 경계와 활성 방을 쓴다.

## 6. 영향 범위 (코드 조사 결과)

`room`/`room.points` 직접 사용 파일: `store/{types,useDocStore,useEditStore,useTraceStore,sample}.ts`, `io/{validate,persist,importFile}.ts`, `scene/{Scene,collision,geometry,CornerEditLayer,useSceneKeys,useWarnings,CameraRig,handles}.ts*`, `trace/{trace,draw}.ts`, `ui/{RoomDialog,RoomPreview,roomForm,WallEditor,DimensionPanel,placement,fixturePlacement,TraceScreen,PanelSections}.tsx`. `useDocStore.partialize`·`equality`·`persist` 구독의 참조 비교는 `rooms`로 바꿔야 한다.

## 7. 구현 단계 (작은 단위, 단계마다 QA 후 커밋)

1. **모델·스키마:** 타입, `validate`(1.0/1.1, 방 겹침, 상한), 스토어(`rooms`, 방 추가·수정·삭제), 저장·불러오기·자동 저장 호환. UI는 방 1개일 때 동일하게 동작해야 한다.
2. **판정 일반화:** 다중 방 `nearestWall`, `computeWarnings`, 문 열림, 고정 요소 배치, 가구 초기 위치.
3. **장면·활성 방 UI:** 방별 렌더, 활성 방 선택, 방 목록 섹션, 카메라 범위, 편집 핸들 활성 방 한정.
4. **방 추가 흐름:** 사각형·ㄱ자 추가, 트레이싱·그리기 다중 방, 이웃 스냅, 겹침 검증.
5. **문서 동기화:** PRD·와이어프레임 갱신, `roomfit-conventions` 스킬의 JSON 스키마 항목 갱신, 브라우저 점검표 갱신.

## 8. 빌더에게 맡기는 것

- 방 겹침 검사 알고리즘(볼록하지 않은 다각형 포함), 스냅 반경·간격 상수의 최종 값, 벽 렌더에서 겹치는 링의 중복 제거 방식.
- `WALL_THICKNESS` 실제 값에 따른 "벽 간격" 상수 확정.
- 방 목록 UI의 구체적 모양(`docs/wireframes.md` 패널 구조에 맞춤).

## 9. 내 판단으로 정한 것 (사용자가 확인 필요)

- 저장 버전 1.1로 올리고 이전 앱 버전은 새 파일을 읽지 못한다.
- 방 상한 20개, 전체 바운딩 박스 10000cm, 스냅 반경 15cm.
- 방 삭제 시 가구는 남긴다.
- 방 사이 간격 모델(내부 치수 + 벽 겹침)을 쓰며 벽에 문 모양 구멍은 뚫지 않는다. 간격은 0 이상이면 모두 허용하고 간격 0은 열린 구조다.
- 음수 좌표를 두지 않고, 새 방 확정 때 문서 전체를 옮겨 불변식을 유지한다. 방을 직접 끌어 옮기는 기능은 넣지 않는다.
- 가구 소속은 중심점 기준, 문·창은 호스트 벽 방 기준. 호스트 변 거리가 같으면 배열 앞쪽 방.
- 트레이싱 이미지·축척은 저장하지 않고 세션에만 둔다.
