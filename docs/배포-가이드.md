# 배포 가이드 (Vercel + d-gong.store)

정적 사이트(서버·DB 없음)라 Vercel 무료(Hobby) 플랜으로 충분하다. 단, Hobby는 **비상업 용도** 약관이므로 광고·제휴 수익을 붙이는 시점에는 Pro 플랜 필요 여부를 Vercel 약관에서 확인한다.

## 1. 사전 확인

| 항목 | 값 |
| --- | --- |
| 저장소 | `https://github.com/peaceseungheon/roomfit-3d` (main) |
| 빌드 명령 | `npm run build` (`tsc -b && vite build`) |
| 출력 폴더 | `dist` |
| 프레임워크 | Vite (자동 감지) |
| Node | 20 이상 |
| 도메인 | `d-gong.store` (apex) → 정본 주소. `www`는 apex로 리디렉션 |

로컬 확인: `npm run build && npx vite preview` 후 `http://localhost:4173`에서 랜딩·에디터·오프라인(개발자도구 Offline)을 점검한다. 서비스 워커는 프로덕션 빌드에서만 등록된다.

## 2. Vercel 프로젝트 만들기

1. main 브랜치를 GitHub에 푸시한다 (`git push origin main`).
2. Vercel 대시보드 → **Add New → Project** → `roomfit-3d` 저장소 Import.
3. Framework Preset `Vite`, Build Command·Output Directory는 기본값 그대로 둔다(위 표와 같다).
4. 환경 변수는 없다(광고·제휴 설정은 코드 상수). **Deploy**.
5. 완료되면 `*.vercel.app` 주소에서 먼저 동작을 확인한다.

이후 main에 푸시할 때마다 프로덕션 배포, 다른 브랜치·PR은 프리뷰 배포가 자동으로 만들어진다.

저장소의 `vercel.json`이 하는 일:
- `/sw.js`: 항상 재검증(`max-age=0, must-revalidate`) → 새 버전이 자동 업데이트(FR-20)로 바로 반영된다.
- `/assets/*`: 파일명에 해시가 붙으므로 1년 `immutable` 캐시.
- 전 경로: `nosniff`, `Referrer-Policy` 보안 헤더.

## 3. 도메인 연결 (d-gong.store)

1. Vercel → 프로젝트 **Settings → Domains → Add** → `d-gong.store` 입력.
2. 추가로 `www.d-gong.store`를 넣고 **Redirect to d-gong.store**(apex)로 지정한다. 같은 내용이 두 주소에 뜨면 검색 중복이 생기므로 하나만 정본으로 둔다.
3. Vercel이 화면에 보여주는 DNS 값을 도메인 등록업체(DNS 관리 화면)에 입력한다. 값은 프로젝트별로 표시되므로 **화면에 나온 값을 그대로** 쓴다. 일반적인 형태는 다음과 같다.

   | 호스트 | 종류 | 값 |
   | --- | --- | --- |
   | `@` | A | Vercel이 안내한 IP (예전 기본값 `76.76.21.21`) |
   | `www` | CNAME | Vercel이 안내한 값 (예: `cname.vercel-dns.com`) |

   대안: 네임서버를 Vercel(`ns1.vercel-dns.com`, `ns2.vercel-dns.com`)로 바꾸면 레코드를 Vercel에서 관리한다.
4. 기존 `@`·`www`의 다른 A/AAAA/CNAME 레코드(주차 페이지 등)는 지운다.
5. 상태가 **Valid Configuration**이 되면 HTTPS 인증서가 자동 발급된다(수 분~최대 수 시간, DNS 전파 시간).
6. 확인: `https://d-gong.store` 접속, `http://`와 `www`가 `https://d-gong.store`로 이동하는지 본다.

## 4. 배포 직후 점검

- [ ] `https://d-gong.store/` 랜딩 → [시작하기] → 에디터 진입, 샘플 방 렌더링
- [ ] 가구 추가·선택 시 제휴 카드가 보이고 새 탭으로 쿠팡이 열린다
- [ ] 저장(자동)·JSON 내보내기·PNG 캡처 동작
- [ ] 개발자도구 Application → Service Workers에 `sw.js`가 활성, Offline 체크 후 새로고침해도 열린다
- [ ] 두 번째 배포 후 새로고침 시 새 버전이 적용된다(자동 업데이트)
- [ ] 휴대폰에서 "홈 화면에 추가"/설치 동작
- [ ] `https://d-gong.store/robots.txt`, `/sitemap.xml`이 열린다
- [ ] 콘솔 오류 없음. 광고·제휴 요청 외 외부 요청 없음(PRD §6)

## 5. 검색 최적화(SEO) 현황

2026-11-24 코드 점검 결과. ✅는 반영 완료, ⬜는 운영자 작업.

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| `<html lang="ko">`, viewport | ✅ | 3개 페이지 모두 |
| 랜딩 `<title>`·description | ✅ | 핵심 키워드(가구 배치, 치수, 3D) 포함 |
| 랜딩 h1 1개, 계층 h2 | ✅ | 사용법·치수 가이드·FAQ 본문이 HTML에 있어 크롤러가 읽는다 |
| canonical (`https://d-gong.store/`, `/privacy.html`) | ✅ | 이번에 추가 |
| Open Graph·Twitter 카드, JSON-LD(WebApplication) | ✅ | 이번에 추가 |
| `robots.txt`, `sitemap.xml` | ✅ | `public/`에 추가. 도메인을 바꾸면 두 파일과 canonical을 함께 수정 |
| 에디터 `noindex` | ✅ | 에디터는 JS 앱이라 본문이 없다. 색인 대상은 랜딩·방침 |
| 모바일 대응, HTTPS | ✅ | 반응형 CSS, Vercel 자동 HTTPS |
| 랜딩 성능 | ✅ | 랜딩은 가벼운 정적 문서, 3D 번들은 에디터만(AC-18-2) |
| **OG 이미지**(`og:image`, 1200×630) | ⬜ | 공유 미리보기용. 이미지를 만들어 `public/og.png`로 두고 `og:image` 메타 추가 |
| **Search Console 등록** | ⬜ | 아래 6절 |
| **네이버 서치어드바이저 등록** | ⬜ | 국내 검색 비중이 커서 필수 |
| 개인정보처리방침 문의처·시행일 | ⬜ | `src/landing/config.ts`의 `CONTACT_EMAIL`, `EFFECTIVE_DATE`가 비어 있어 방침에 표시되지 않는다. 광고·제휴 심사 전에 채운다 |
| 콘텐츠 | ⬜ | 신규 도메인은 노출까지 수 주 걸린다. "원룸 가구 배치", "침대 크기 가이드" 같은 정적 안내 페이지를 늘리면 유리(늘릴 때 sitemap에 추가) |

한계: 이 점검은 코드·빌드 산출물 기준이다. 실제 색인·순위는 배포 후 검색 콘솔에서 확인해야 한다.

## 6. 검색 엔진 등록

1. **Google Search Console**: 속성 추가 → 도메인 `d-gong.store` → 안내하는 TXT 레코드를 DNS에 추가해 소유 확인 → Sitemaps에 `sitemap.xml` 제출 → URL 검사로 `https://d-gong.store/` 색인 요청.
2. **네이버 서치어드바이저**: 사이트 등록 `https://d-gong.store` → 소유 확인(HTML 태그 또는 파일) → 사이트맵 제출 → 웹페이지 수집 요청. HTML 태그 방식은 `index.html`의 `<head>`에 메타를 넣고 재배포한다.
3. 등록 후 1~2주 뒤 색인 상태(색인 생성됨/제외됨)를 확인한다.

## 7. 수익화 연동 시 할 일

- **쿠팡 파트너스**: 활동 채널에 `https://d-gong.store`를 등록한다(PRD OPEN-03). 링크 자체는 이미 코드에 들어 있다.
- **애드센스**: 도메인 추가·사이트 심사 → `ADSENSE_CLIENT`, `ADSENSE_SLOT` 입력 후 재배포. 개인정보처리방침과 동의 배너가 필요하다(이미 구현, 법무 검토는 OPEN-04). `ads.txt`가 요구되면 `public/ads.txt`에 추가한다.
  - **에디터 측면 광고 켜기**(꺼진 상태로 출시, AC-18-1): ① 애드센스에서 세로형(160x600) 디스플레이 단위를 만든다 → ② `src/landing/config.ts`의 `EDITOR_AD_SLOT`에 슬롯 ID `9725198699`를 넣는다(승인 후) → ③ 애드센스 대시보드 자동 광고 설정에서 `/editor.html` 페이지를 제외한다(안 하면 캔버스 위에 앵커·전면 광고가 뜬다, AC-18-3) → ④ 재배포. 슬롯이 비어 있으면 칸도 스크립트 요청도 없다.

## 8. 운영·롤백

- 배포 이력: Vercel **Deployments**. 문제가 생기면 이전 배포의 **Promote to Production**(Instant Rollback)로 즉시 되돌린다.
- 서비스 워커 캐시 때문에 롤백 직후 일부 사용자는 이전 번들을 잠시 볼 수 있다. `sw.js`가 항상 재검증되므로 다음 방문에 정리된다.
- 사용자 데이터는 브라우저 LocalStorage에만 있어 서버 쪽 백업·마이그레이션은 없다. 저장 스키마를 바꾸는 배포는 옛 파일이 읽히는지(AC-14-3) 먼저 테스트한다.
