# RoomFit 3D — PRD (MVP v1.0)

> 근거: `docs/기획서.md` + 착수 인터뷰 합의(2026-11-16). 화면 명세는 `docs/wireframes.md`.
> 독자: 이 문서만 읽고 구현에 착수하는 AI 에이전트. 표기: **[확정]** 인터뷰·기획서 합의 / **[기본값]** 합의되지 않아 PRD가 둔 임시값(변경 가능, §9에 모음) / **[미결정]** §8.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 실제 가구 치수로 가상 공간 배치를 시뮬레이션하고 동선·문 열림 간섭을 사전 검증하는 웹 3D 유틸리티 |
| 대상 | 이사·인테리어 준비 또는 구매 전 공간을 확인하려는 모든 사용자. 가구 수·주거 형태를 한정하지 않는다. (기획서 §1의 "1~2인 가구" 한정을 이 PRD가 대체한다) [확정, 2026-11-18] |
| 핵심 가치 | 렌더링 품질보다 **치수 검증**, 낮은 입력 피로도, **무가입·무설치** |
| 플랫폼 | 웹, 데스크톱·태블릿·모바일 전체 반응형 [확정] |
| 스택/단위 | React+Vite+TS, R3F, Zustand+Zundo. 1unit=1cm (`roomfit-conventions` 참조) |

## 2. 범위

**MVP 포함 [확정]:** 단층 직선 벽 방, 직사각형·ㄱ자 프리셋, 평면도 트레이싱, 모서리 편집, 문/창/콘센트 마커, 문 열림 부채꼴, 기본 가구 + 치수 박스, 10cm 스냅, 충돌 경고, 2D/쿼터/1인칭 뷰, Undo/Redo, LocalStorage·JSON 입출력, 화면 캡처, 모바일 포함 반응형.

**MVP 포함(보조) [확정]:** 자동 모서리 제안(FR-19, 브라우저 내 영상처리, API 키·서버 없음). 생성형 AI 평면도 분석은 비용·서버가 필요해 MVP에서 제외하고 v1.1 후보로 둔다(OPEN-05).

**MVP 포함(수익화) [확정]:** 제휴 구매 링크(FR-17), 비침습형 광고(FR-18). 수익 모델 검토 결과는 §11.

**MVP 제외(v2.0):** 복층·계단, 곡선 벽, 천장 몰딩, 브랜드 가구 DB, 고해상도 텍스처, 그림자·조명, 물리 엔진, WASD 보행, 클라우드 계정, 실시간 공동 편집, Pro 유료 플랜, B2B 제휴(§11에서 검토 후 제외), 여러 가구를 조립해 한 가구로 만드는 기능(치수 자유 변경으로 충분하다고 판단해 제외).

## 3. 사용자 흐름

1. 랜딩 "시작하기" → 가입 없이 에디터 진입, 기본 원룸 샘플이 이미 렌더링됨 (FR-01, FR-02)
2. 방 만들기: 프리셋(치수 입력) 또는 평면도 트레이싱 (FR-03, FR-04, FR-05)
3. 문·창·콘센트 배치, 문 열림 부채꼴 확인 (FR-06, FR-07)
4. 가구 선택·배치, 치수 박스로 구매 예정 가구 크기 입력 (FR-08, FR-09, FR-10)
5. 경고 확인, 시점 전환으로 검증 (FR-11, FR-12)
6. 자동 저장, JSON 내보내기, 캡처 (FR-14, FR-15)

## 4. 기능 요구사항

각 수용 기준(AC)은 그대로 테스트 케이스가 될 수 있는 문장이다. "화면" 열은 `wireframes.md`의 화면 ID.

### FR-01 즉시 진입 (화면 S-01, S-02)
- AC-01-1: 랜딩에서 "시작하기"를 누르면 로그인·가입 없이 1회의 이동으로 에디터가 열린다.
- AC-01-2: LocalStorage에 저장본이 있으면 "시작하기"는 샘플 대신 저장본으로 에디터를 연다. 없으면 FR-02 샘플로 연다. (별도의 "이어하기" 버튼은 두지 않는다. 샘플로 돌아가려면 FR-14의 "샘플로 초기화"를 쓴다.)
- AC-01-3: 랜딩은 광고 승인을 위한 **고유 정적 콘텐츠**를 갖는다: ① 사용법 3단계(방 만들기→가구 넣기→간섭 확인) ② 가구 치수 가이드(FR-08 기본 가구 15종의 치수표와 "배치 전에 재야 할 치수" 안내) ③ 자주 묻는 질문 ④ 개인정보처리방침 링크. 콘텐츠는 코드에 포함된 정적 텍스트이며 서버·CMS를 두지 않는다. [확정: 2026-11-18, 애드센스 승인 대응]
- AC-01-4: 개인정보처리방침은 S-01의 하위 정적 페이지로 두고 랜딩 하단과 동의 배너(S-07)에서 연결한다. 광고·제휴·로컬 저장(LocalStorage)·외부 요청 목록(§6)과 "광고로 제3자가 쿠키를 저장하거나 IP 정보를 수집할 수 있음" 고지를 포함한다(애드센스 게시자 정책). 법무 검토는 OPEN-04. [기본값]

### FR-02 기본 원룸 샘플 (S-02)
- AC-02-1: 첫 진입 시 **400×300cm, 천장 230cm** 직사각형 방과 문 1개, 가구 2개 이상이 렌더링된 상태다. [기본값]
- AC-02-2: 샘플은 사용자가 편집·삭제할 수 있다. 샘플 상태에서 사용자가 첫 편집을 하기 전까지는 자동 저장(AC-14-1)이 LocalStorage에 쓰지 않는다.

### FR-03 프리셋 방 생성 (S-03)
- AC-03-1: 프리셋 선택지는 **직사각형**과 **ㄱ자** 두 가지뿐이다. [확정]
- AC-03-2: 직사각형은 가로·세로(cm), ㄱ자는 가로·세로와 잘려나가는 영역의 가로·세로(cm), 공통으로 천장고(cm)를 입력한다. 잘려나가는 영역은 **우상단 모서리**로 고정하고, 회전·반전은 방 생성 후 가구와 무관하게 지원하지 않는다. [기본값]
- AC-03-3: 입력이 정수가 아니거나 범위 밖이면 필드 아래에 오류 문구가 표시되고 "만들기"가 비활성화된다. 범위: 가로·세로 100cm 이상 **방 크기 상한(3000cm) 이하**(OPEN-02 확정), 천장고 180~400cm, ㄱ자 잘림 영역은 가로·세로 각각 전체보다 작고 50cm 이상. [기본값]
- AC-03-4: 확정하면 기존 방이 새 방으로 교체되며 이 동작은 Undo로 되돌릴 수 있다. 교체 전에 기존 가구가 있으면 "가구는 유지/삭제" 중 선택하게 한다. [기본값: 유지, 방 밖이 된 가구는 경고 표시]

### FR-04 평면도 트레이싱 (S-04)
- AC-04-1: PNG/JPG 이미지를 업로드하면 2D 뷰 배경으로 표시된다. 지원 형식이 아니면 오류 토스트를 표시하고 상태를 바꾸지 않는다.
- AC-04-2: 사용자가 이미지 위의 두 점을 찍고 실제 길이(cm)를 입력하면 **기준선 1개**로 축척이 결정되며, 이후 클릭 좌표가 cm로 변환된다. [확정]
- AC-04-3: 모서리를 순서대로 클릭하면 점이 추가되고, 첫 점을 다시 누르거나 "닫기"를 누르면 다각형이 닫혀 3D 벽체가 생성된다. 점이 3개 미만이면 닫기가 비활성화된다.
- AC-04-4: 선분이 서로 교차하는 다각형은 닫을 수 없고 교차 구간에 오류 표시와 안내 문구를 보여준다.
- AC-04-5: 축척을 설정하기 전에는 모서리 찍기가 비활성화되고 안내 문구를 보여준다.
- AC-04-6: 배경 이미지는 저장 JSON에 포함하지 않는다(용량). 불러오기 후에는 배경 없이 방만 복원된다. [기본값]

### FR-05 모서리 편집 (S-02, S-04)
- AC-05-1: 2D 뷰에서 방 모서리 점을 드래그하면 벽체가 실시간으로 갱신되고, 위치는 스냅이 켜져 있을 때 10cm 단위로 맞춰진다. [모서리 편집은 확정, 스냅 적용은 기본값]
- AC-05-2: 벽 선분을 선택하면 길이(cm) 입력 필드가 나타나고, 값을 바꾸면 해당 벽의 한쪽 끝점이 이동하여 길이가 맞춰진다.
- AC-05-3: 편집 결과가 교차 다각형이 되면 편집이 취소(원위치)되고 오류 토스트를 표시한다.
- AC-05-4: 모서리 편집으로 문·창이 붙어 있던 벽이 사라지거나 짧아지면 해당 고정 요소는 가장 가까운 벽 위로 이동하고, 들어갈 자리가 없으면 경고 표시 후 유지한다.
- AC-05-5: 점 추가/삭제는 MVP에서 제공하지 않는다(트레이싱 단계에서만 점 추가). [기본값]

### FR-06 고정 요소 배치 (S-02, S-05)
- AC-06-1: 종류는 현관문, 방문, 창문, 콘센트이다. [확정]
- AC-06-2: 패널의 고정 요소 버튼(현관문·방문·창문·콘센트)을 누르면 가장 긴 벽의 빈 구간 중앙에 벽에 붙어 추가되고, 이후 벽을 따라 드래그할 수 있다. 벽을 클릭해 배치하는 방식은 제공하지 않는다. (구현에 맞춰 수정(2026-11-19))
- AC-06-3: 문·창은 폭(cm)과 높이(cm)를 입력해 바꿀 수 있고, 벽 길이를 넘는 값은 벽 길이로 제한한다. 기본값: 문 90×210, 창 120×110(바닥 위 90). 창은 바닥 위 높이도 입력할 수 있다. [기본값]
- AC-06-5: 콘센트는 폭·높이 없이 바닥 위 높이만 입력하며 기본 30cm이다. 창·콘센트는 문 전용 항목(여는 방향·열리는 쪽)을 숨긴다. [기본값]
- AC-06-4: 같은 벽에서 문/창끼리 겹치는 위치로 이동하면 겹침 경고(FR-11 동일 스타일)를 표시한다. 이동은 막지 않는다.

### FR-07 문 열림 반경 (S-02, S-05)
- AC-07-1: 모든 여닫이 문에 대해 바닥에 부채꼴을 표시한다. [확정] 반경은 문 폭과 같고 각도는 90°로 한다. [기본값: 기획서 예시(폭 90, 반경 90, 각도 90)에서 일반화]
- AC-07-2: 문 속성에서 여는 방향(좌/우)과 열리는 쪽(실내/실외)을 바꾸면 부채꼴이 즉시 바뀐다. 방향 조합은 4가지(좌·실내, 우·실내, 좌·실외, 우·실외)이며, 기획서에는 좌·실내(`LEFT_IN`)만 예시로 있고 나머지 3가지 값 이름은 `RIGHT_IN`, `LEFT_OUT`, `RIGHT_OUT`으로 한다. [기본값]
- AC-07-3: 실외로 열리는 문의 부채꼴은 방 밖에 그려지며 충돌 판정에서 제외한다. [기본값]

### FR-08 가구 배치 (S-05, S-02)
- AC-08-1: 카탈로그에서 가구를 고르면(데스크톱: 클릭, 터치: 탭) 방 중앙 근처에 배치되고 즉시 선택 상태가 된다.
- AC-08-2: 카탈로그는 아래 **15종**을 제공하고, 종류마다 아래 기본 크기로 배치된다. 목록은 한 곳의 상수 배열로 관리한다. [확정: OPEN-01, 2026-11-18]
- AC-08-5: 가구 정면은 회전 0°일 때 +z 방향(2D 평면도에서 아래쪽)이다. 벽에 붙이는 가구의 뒷면은 -z 쪽이다. [확정: OPEN-01]
- AC-08-6: 배치 후에는 어느 종류든 W×D×H를 AC-09-2대로 자유롭게 바꿀 수 있으므로 기본 크기는 시작값일 뿐이다. 여러 가구를 조립해 한 가구로 만드는 기능은 제공하지 않는다. [확정]

- AC-08-7: 가구는 **종류별 색을 입힌 직육면체 블록**으로 렌더링하며 GLB 모델을 사용하지 않는다. 크기를 바꿔도 비율이 일그러지지 않고 W×D×H가 그대로 보인다. 블록 위에 종류 이름 라벨을 표시한다. [확정, 2026-11-18] 이에 따라 기획서 §4.2·§6-1의 GLB 에셋 수집·변환(`@react-three/gltfjsx`)은 MVP에서 하지 않는다.
- AC-08-8: 치수 박스(FR-09)는 반투명 스타일을 유지해 불투명한 가구 블록과 구분한다.
- AC-08-3: 가구는 `y=0` 바닥 평면 위에서만 이동한다(공중 부양 불가).
- AC-08-4: 선택된 가구는 삭제(Delete 키 또는 삭제 버튼), 복제, 90° 회전("+90°" 버튼 또는 R 키)이 가능하다. 회전 버튼은 +90° 하나뿐이며 좌/우 두 개로 나누지 않는다. (구현에 맞춰 수정(2026-11-19))

### FR-09 치수 박스 / 치수 커스텀 (S-05)
- AC-09-1: 우측 패널 카탈로그 아래의 "치수 박스" 생성 폼에서 **가로(W)·깊이(D)·높이(H)**(cm)를 입력하고 "치수 박스 추가"를 누르면 해당 크기의 가이드 박스가 만들어진다. W/D/H 필드는 빈 값으로 시작하며(기본 크기를 미리 채우지 않음) 별도 "모드"는 없다. 저장 `modelType`은 `DIMENSION_BOX`. [확정] (구현에 맞춰 수정(2026-11-19))
- AC-09-2: 기본 가구도 선택 후 같은 W/D/H 필드로 크기를 바꿀 수 있다.
- AC-09-3: 입력 순서·표시는 W×D×H, 저장 `size`는 [x(W), y(H), z(D)]이며 변환은 `src/ui/` 한 곳에서만 한다.
- AC-09-4: W/D/H는 1 이상의 정수(cm)이며, 가로·깊이는 최대 1000, 높이는 최대 500이다. 범위 밖 입력은 필드 오류를 표시하고 값을 반영하지 않는다. [기본값, 방 크기 상한(OPEN-02)과는 별개 값]
- AC-09-5: 치수 박스는 이름(선택, 최대 100자)과 색상을 지정할 수 있다. 기본 색은 `#90caf9`이고 불투명도 0.45의 반투명으로 렌더링되어 가구와 구분된다. (구현에 맞춰 수정(2026-11-19))

### FR-10 이동·회전·스냅 (S-02)
- AC-10-1: 이동 좌표는 항상 10cm 단위로 스냅된다. [확정]
- AC-10-2: 스냅 토글을 끄면 1cm 단위로 이동할 수 있다. [기본값: 기본 켜짐]
- AC-10-3: 회전은 "+90°" 버튼(하나)·R 키 외에 각도 입력(도)도 허용하되 0~359 정수만 받는다. 저장은 도(degree). [기본값] (구현에 맞춰 수정(2026-11-19): 좌/우 두 버튼 아님)
- AC-10-4: 터치 환경에서는 한 손가락 드래그가 선택된 가구 이동, 빈 곳 드래그가 카메라 이동이다.
- AC-10-5: 가구를 선택한 상태에서 방향키를 누르면 스냅 설정과 같은 단위(켬 10cm, 끔 1cm)로 이동한다. [기본값]

### FR-11 충돌·경고 (S-02, S-05) [확정: 경고만, 배치 허용]
- AC-11-1: 다음 3종 간섭 중 하나라도 `Box3.intersectsBox`가 참이면 해당 가구(또는 고정 요소)를 붉은색으로 하이라이트한다: ① 가구↔가구 ② 가구↔문 열림 반경 ③ 가구↔벽.
- AC-11-2: 어떤 경고 상태에서도 배치·이동·크기 변경은 **막지 않는다**.
- AC-11-3: 경고가 해소되면 하이라이트가 즉시 사라진다.
- AC-11-4: 화면에 현재 경고 개수가 표시되고, 누르면 경고 목록(가구 이름 + 간섭 종류)이 열린다. 항목을 누르면 해당 가구가 선택된다.
- AC-11-5: 방 밖으로 나간 가구는 "벽 간섭"으로 취급한다.
- AC-11-6: 부채꼴은 박스 근사(`Box3`)로 판정한다(원호 정밀 판정은 MVP 제외). [기본값]

- AC-13-3: 실행 취소 가능 단계가 없으면 버튼이 비활성화된다. 단계 수 상한 50. [기본값]

### FR-14 저장·불러오기 (S-06, S-07)

- AC-14-2: "내보내기"는 기획서 §5 스키마(`projectInfo`, `room`, `items`)의 `.json` 파일을 내려받는다.
- AC-14-3: "불러오기"는 `.json`을 읽어 `version`, 필수 필드, 숫자 범위를 검증한다. 검증 실패 시 **기존 상태를 유지**하고 실패 사유(필드 경로)를 포함한 오류를 표시한다.
- AC-14-4: 불러오기 성공 시 현재 작업을 덮어쓰기 전에 확인 대화상자를 보여주고, 확정하면 Undo로 되돌릴 수 있다.
- AC-14-5: LocalStorage 쓰기가 실패(용량·차단)하면 저장 상태 표시가 "저장 실패"로 바뀌고 JSON 내보내기를 권유한다.
- AC-14-6: "샘플로 초기화"를 선택하면 확인 대화상자를 거쳐 방과 가구를 FR-02 샘플로 되돌린다. 이 동작은 Undo로 되돌릴 수 있다. [기본값]

- AC-16-2: 모든 구간에서 FR-01~FR-19의 기능에 접근할 수 있다(기능 삭제로 대응하지 않는다).

### FR-19 자동 모서리 제안 (S-04) — 브라우저 내 영상처리, AI·API 키 없음
평면도 이미지에서 방 윤곽 모서리를 **제안**한다. 외부 서비스·API 키·서버를 쓰지 않고 브라우저에서 계산한다. 치수 검증이 핵심 가치이므로 실제 길이는 항상 사용자의 기준선 입력과 확인으로 정한다. (AI 분석은 v1.1 후보, §2·OPEN-05)
- AC-19-1: S-04의 ① 이미지 업로드 후 "윤곽 자동 제안" 버튼이 표시된다. 사용하지 않아도 수동 트레이싱(FR-04)은 모든 단계가 그대로 동작한다.
- AC-19-2: 처리는 브라우저 안에서만 한다. 이미지는 어떤 외부 서버로도 전송하지 않는다.
- AC-19-3: 제안 알고리즘은 이미지의 가장 큰 닫힌 윤곽을 찾아 다각형으로 단순화한 모서리 점 목록을 만든다. 구현 방식(순수 JS 또는 영상처리 라이브러리)은 구현 단계에서 정하되, 라이브러리를 추가하면 이유와 번들 크기를 보고한다. [기본값]
- AC-19-4: 처리 전에 이미지를 긴 변 1600px 이하로 축소해 계산하고, 결과 점은 원본 이미지 좌표로 환산한다. [기본값]
- AC-19-5: 결과는 계산이 끝나면(① 직후) 이미지 위에 **점선(미확정) 점**으로 표시한다. 사용자가 기준선으로 축척을 설정(AC-04-2)하고 "적용"을 눌러야 실선 점이 되며, 그 전에는 방을 만들 수 없다. 적용 후에는 점을 드래그해 보정할 수 있다(FR-05).
- AC-19-6: 이미지의 글자(치수 표기)는 읽지 않는다. 축척은 항상 기준선으로 정한다.
- AC-19-7: 결과는 점 3개 이상, 이미지 범위 안, 자기 교차 없음(AC-04-4)을 만족해야 한다. 만족하지 못하거나 윤곽을 찾지 못하면 "윤곽을 읽지 못했습니다. 직접 찍어 보세요" 토스트를 표시하고 기존 트레이싱 상태를 유지한다.
- AC-19-8: 계산은 5초 안에 끝나야 한다. 넘으면 중단하고 AC-19-7과 같은 안내를 표시한다. 계산 중에는 진행 표시와 취소 버튼을 보이고, 화면은 멈추지 않는다. [기본값: 5초]
- AC-19-9: 같은 계산은 동시에 1개만 실행한다. 취소하거나 이미지를 바꾸면 이전 결과를 버린다.

### FR-17 제휴 구매 링크 (S-05) — 수익화
배경·근거는 §11. 사용자가 구매하려는 가구의 치수를 이미 입력한다는 점을 수익 접점으로 쓴다.
- AC-17-1: 기본 가구 15종(FR-08) 중 하나를 선택하면 속성 패널(S-05)에 "이 종류 상품 보기 ↗" 링크가 표시된다. 치수 박스(FR-09)와 종류가 없는 항목에는 표시하지 않는다.
- AC-17-2: 링크는 새 탭으로 열리고, 종류(예: BED_SINGLE)마다 **미리 만들어 둔 쿠팡 파트너스 제휴 URL**로 간다(`rel="sponsored noopener noreferrer"`). URL은 코드 상수의 정적 값이며 앱은 방 구조·배치·치수 등 어떤 사용자 정보도 URL에 담지 않는다. 사용자가 치수를 바꿔도 링크는 종류별로 고정이다. [확정: 2026-11-18, 쿠팡은 검색 URL을 사람이 변환하는 방식이라 즉석 생성 불가]
- AC-17-3: 링크 바로 옆에 "제휴 링크입니다. 구매 시 수수료를 받을 수 있습니다" 문구를 항상 함께 표시한다. 문구 없이 링크만 노출하는 상태는 허용하지 않는다.
- AC-17-4: 링크는 어떤 기능도 막거나 선행 조건으로 요구하지 않는다. 링크 클릭 여부와 관계없이 편집·저장·내보내기는 동일하게 동작한다.
- AC-17-5: 제휴 링크 설정은 종류별 URL 맵 1개를 코드 상수 한 곳에서 관리한다. 맵에 URL이 없는 종류는 링크 자체를 표시하지 않고, 전체가 비어 있으면 기능이 숨겨진다. 대표 검색어(예: 싱글침대 100x200)와 변환 방법은 운영 메모로 남긴다.
- AC-17-6: 링크 URL은 운영자가 쿠팡 파트너스 [간편 링크 만들기]로 종류별 검색 결과 URL을 변환해 상수에 넣는 사전 작업의 결과다(상품 DB 불필요). 작업이 끝난 종류부터 AC-17-5에 따라 링크가 나타난다. 출시 전 15종을 모두 채우는 것이 목표이나 미완 종류가 있어도 출시는 막지 않는다(해당 종류만 링크 숨김). [기본값]

### FR-18 비침습형 광고 (S-01, S-06 동의 토글, S-07) — 수익화
- AC-18-1: 광고 노출 위치는 **랜딩(S-01) 콘텐츠 영역 안 1칸**뿐이다. 광고 수는 콘텐츠보다 적어야 한다. [확정: 2026-11-18, 애드센스 정책(도구 화면·콘텐츠 없는 화면 광고 금지) 대응으로 메뉴 시트 광고 삭제]
- AC-18-2: 랜딩은 에디터와 별도 문서(별도 페이지 로드)이다. 에디터 문서(S-02~S-07)에는 광고를 표시하지 않으며 광고 스크립트도 로드하지 않는다.
- AC-18-3: 전면·팝업·자동 재생 영상·화면 이동 유도 광고를 사용하지 않는다.
- AC-18-4: 광고 영역은 크기를 미리 예약해 광고 로드 전후로 레이아웃이 밀리지 않는다(레이아웃 이동 없음). 광고가 로드되지 않거나 차단돼도 빈 영역 대신 영역이 접히고 기능에 영향이 없다.
- AC-18-5: 광고 스크립트는 사용자가 개인정보·쿠키 동의 배너(S-07)에서 허용한 뒤에만 로드한다. 거부 또는 미응답 상태에서는 어떤 광고 요청도 보내지 않고 광고 영역을 접는다.
- AC-18-6: 동의 선택은 LocalStorage에 저장되며, 메뉴(S-06)에서 언제든 바꿀 수 있다.
- AC-18-7: 광고 설정(네트워크 ID, 슬롯 ID)은 코드 상수 한 곳에서 관리하고, 값이 비어 있으면 광고 영역, 동의 배너, 메뉴(S-06)의 동의 토글을 모두 표시하지 않는다.

## 6. 비기능 요구사항
- 성능: 가구 30개 기준 데스크톱 60fps 목표, 모바일 30fps 이상 [기본값].
- 접근성: 모든 버튼에 텍스트 또는 `aria-label`, 포커스 표시, 경고는 색상 외에 아이콘/텍스트로도 표시(색약 고려). 토스트는 오류·경고(문구가 ⚠로 시작)면 `role="alert"`, 그 외는 `role="status"`이며, 폼 필드 오류는 `aria-describedby`로 연결하고 `alert`를 쓰지 않는다. (구현에 맞춰 추가(2026-11-19))
- 브라우저: 최신 Chrome/Edge/Safari/Firefox. WebGL 미지원 시 랜딩은 안내 문구를 표시하고, 에디터는 캔버스 영역을 "이 브라우저는 3D를 지원하지 않습니다. 최신 Chrome/Edge/Safari/Firefox를 사용하세요." 안내로 대체한다(패널 편집·자동 저장은 그대로 동작) [기본값]. 3D 컨텍스트가 소실되면 캔버스를 "화면을 다시 불러오는 중…" 오버레이로 덮고, 5초 안에 복구되지 않으면 [새로고침] 버튼을 표시한다 [기본값]. (구현에 맞춰 수정(2026-11-19))
- 배포: 루트 도메인에 배포한다(하위 경로 배포 아님). [확정: 2026-11-19]
- 개인정보: 방·가구 데이터는 서버로 전송하지 않고 브라우저 로컬에만 저장한다. 외부로 나가는 요청은 (a) 동의한 경우의 광고 요청(랜딩, FR-18), (b) 사용자가 제휴 링크를 눌렀을 때 쿠팡 파트너스 페이지가 열리는 요청(종류별 고정 URL, 방·가구·치수 정보 미포함, FR-17)뿐이다. 평면도 이미지는 브라우저 밖으로 나가지 않는다(FR-19).
- 운영 비용: 정적 호스팅만 사용하고 자체 서버·DB·로그인을 두지 않는다. 수익 측정은 제휴·광고 네트워크의 대시보드를 쓰며 자체 분석 도구를 만들지 않는다.

## 11. 수익화

### 11.1 전제와 제약
- 핵심 가치는 **무가입·무설치·낮은 입력 피로도**(기획서 §1)다. 수익 모델은 이 가치를 깨지 않아야 한다.
- 서버 없이 정적 호스팅으로 운영하므로 고정 운영비가 매우 낮다. 따라서 목표는 큰 수익이 아니라 **운영비(호스팅·도메인·도구 비용)를 넘는 최소 수익 확보**다.
- 수익을 **보장**할 수는 없다. 이 문서는 수익이 발생할 구조와 손익분기 판단 기준을 정의할 뿐이며, 실제 금액은 트래픽과 제휴·광고 단가에 달려 있다.

### 11.2 검토한 방안과 결정

| 방안 | 결정 | 이유 |
| --- | --- | --- |
| 제휴 구매 링크 | **채택(FR-17)** | 가구를 배치해 보며 구매를 고민하는 맥락이라 구매 의도가 높은 접점이다. 링크가 치수를 반영하지 않으므로 치수 박스에는 표시하지 않는다. 가입·서버 불필요, 구현은 종류별 URL 상수 |
| 비침습형 광고 | **채택(FR-18)** | 가입 불필요. 단, 편집 경험과 애드센스 정책을 지키기 위해 랜딩에만 노출 |
| Pro 유료 플랜(클라우드 저장·동기화·다중 프로젝트) | 제외 | 계정·결제가 필요해 "무가입" 가치와 충돌하고 기획서상 v2.0(클라우드 계정) 범위. 무료 이용자 규모가 확인된 뒤 재검토 |
| B2B/파트너 제휴(브랜드·이사·인테리어 임베드/리드) | 제외 | 영업이 필요하고 초기 수익이 불확실. 브랜드 가구 DB(v2.0)와 함께 재검토 |

### 11.3 수익 구조

수익은 두 갈래다.

1. **제휴 수수료** = 제휴 링크 클릭 수 × 구매 전환율 × 평균 구매액 × 수수료율
2. **광고 수익** = 광고 노출 수 × 노출당 단가(또는 클릭 수 × 클릭당 단가)

가구는 단가가 높은 품목이라 같은 클릭이라도 건당 수수료가 큰 편이다. 반대로 구매 전환은 방 배치 후 수일~수주 뒤에 일어날 수 있어 초기에 수익이 눈에 보이기까지 시간이 걸린다.

### 11.4 손익분기 판단 기준
- 월 고정 운영비 = 호스팅 + 도메인 + 기타 도구 비용(자체 서버 없음). 실제 값은 선정 후 기입한다.
- 손익분기 조건: `제휴 수수료 + 광고 수익 ≥ 월 고정 운영비`.
- 측정은 제휴·광고 네트워크 대시보드의 월 클릭·전환·노출·수익으로 하고(§6), 자체 분석 도구는 만들지 않는다.
- 임계치와 목표 금액은 OPEN-04 확정과 운영 데이터(쿠팡 수수료 기본 3%, 광고 단가)가 쌓인 뒤 정한다. 지금 수치를 가정해 적지 않는다.

### 11.5 위험과 완화

| 위험 | 완화 |
| --- | --- |
| 광고가 편집 경험·성능을 해침 | 편집 영역 광고 금지(AC-18-2), 영역 크기 예약(AC-18-4), 팝업·전면 광고 금지(AC-18-3) |
| 제휴 링크가 광고성임을 숨김 | 항상 고지 문구 표시(AC-17-3), `rel="sponsored"` |
| 개인정보·쿠키 규제 | 동의 후에만 광고 로드(AC-18-5), 방 데이터는 외부로 보내지 않음(§6), 법무 검토는 OPEN-04 |
| 제휴 약관·심사 미충족 | 운영자 준비 단계(쿠팡 파트너스 가입·정산 조건 확인)에서 확인하고, 미충족이면 설정을 비워 링크를 숨김(AC-17-5) |
| 광고 차단기·낮은 트래픽으로 수익 부족 | 두 갈래 수익 구조 유지, 수익이 운영비에 못 미치면 Pro 플랜(v2.0)을 재검토 |
| 수익 요소가 신뢰를 해침(편향된 추천으로 보임) | 링크는 종류별로 미리 만든 검색 결과일 뿐 특정 상품을 추천하지 않음 |

### 11.6 재검토 시점
- 월 방문자와 제휴 클릭 데이터가 쌓인 뒤 §11.4 손익분기를 점검한다.
- 손익분기에 못 미치고 사용자 요구가 확인되면 Pro 플랜·브랜드 가구 DB 제휴를 별도 PRD로 검토한다.
