# RoomFit 3D — PRD (MVP v1.0)

> 근거: `docs/기획서.md` + 착수 인터뷰 합의(2026-11-16). 화면 명세는 `docs/wireframes.md`.
> 독자: 이 문서만 읽고 구현에 착수하는 AI 에이전트. 표기: **[확정]** 인터뷰·기획서 합의 / **[기본값]** 합의되지 않아 PRD가 둔 임시값(변경 가능, §9에 모음) / **[미결정]** §8.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 실제 가구 치수로 가상 공간 배치를 시뮬레이션하고 동선·문 열림 간섭을 사전 검증하는 웹 3D 유틸리티 |
| 대상 | 이사·인테리어 준비 또는 구매 전 공간을 확인하려는 모든 사용자. 가구 수·주거 형태를 한정하지 않는다. (기획서 §1의 "1~2인 가구" 한정을 이 PRD가 대체한다) [확정, 2026-11-18] |
| 핵심 가치 | 렌더링 품질보다 **치수 검증**, 낮은 입력 피로도, **무가입·무설치** |
| 플랫폼 | 웹, 데스크톱·태블릿·모바일 전체 반응형 [확정] |
| 스택/단위 | React+Vite+TS, R3F, Zustand+Zundo. 1unit=1cm (`roomfit-conventions` 참조) |

## 2. 범위

**MVP 포함 [확정]:** 단층 직선 벽 방, 직사각형·ㄱ자 프리셋, 평면도 트레이싱, 모서리 편집, 문/창/콘센트 마커, 문 열림 부채꼴, 기본 가구 + 치수 박스, 10cm 스냅, 충돌 경고, 2D/쿼터/1인칭 뷰, Undo/Redo, LocalStorage·JSON 입출력, 화면 캡처, 모바일 포함 반응형.

**MVP 포함(보조) [확정]:** 자동 모서리 제안(FR-19, 브라우저 내 영상처리, API 키·서버 없음). 생성형 AI 평면도 분석은 비용·서버가 필요해 MVP에서 제외하고 v1.1 후보로 둔다(OPEN-05).

**MVP 포함(수익화) [확정]:** 제휴 구매 링크(FR-17), 비침습형 광고(FR-18). 수익 모델 검토 결과는 §11.

**MVP 제외(v2.0):** 복층·계단, 곡선 벽, 천장 몰딩, 브랜드 가구 DB, 고해상도 텍스처, 그림자·조명, 물리 엔진, WASD 보행, 클라우드 계정, 실시간 공동 편집, Pro 유료 플랜, B2B 제휴(§11에서 검토 후 제외), 여러 가구를 조립해 한 가구로 만드는 기능(치수 자유 변경으로 충분하다고 판단해 제외).

## 3. 사용자 흐름

1. 랜딩 "시작하기" → 가입 없이 에디터 진입, 기본 원룸 샘플이 이미 렌더링됨 (FR-01, FR-02)
2. 방 만들기·추가: 프리셋(치수 입력), 빈 캔버스 그리기 또는 평면도 트레이싱 — 방 추가에서도 세 방법을 쓴다 (FR-03, FR-04, FR-05)
3. 문·창·콘센트 배치, 문 열림 부채꼴 확인 (FR-06, FR-07)
4. 가구 선택·배치, 치수 박스로 구매 예정 가구 크기 입력 (FR-08, FR-09, FR-10)
5. 경고 확인, 시점 전환으로 검증 (FR-11, FR-12)
6. 자동 저장, JSON 내보내기, 캡처 (FR-14, FR-15)

## 4. 기능 요구사항

각 수용 기준(AC)은 그대로 테스트 케이스가 될 수 있는 문장이다. "화면" 열은 `wireframes.md`의 화면 ID.

### FR-01 즉시 진입 (화면 S-01, S-02)
- AC-01-1: 랜딩에서 "시작하기"를 누르면 로그인·가입 없이 1회의 이동으로 에디터가 열린다.
- AC-01-5: 랜딩은 첫 화면(히어로)에서 시작 경로를 둘로 보여준다: 주 버튼 "시작하기"(AC-01-1·01-2)와 보조 링크 "예시 배치로 시작"(템플릿 카드 구역으로 이동). 같은 구역의 템플릿 카드는 FR-21 템플릿 3종을 `/editor.html#t=<id>`로 연결하고 "배치 가이드 전체 보기" 링크를 둔다. 헤더에 "예시 배치"·"배치 가이드" 링크를 둔다. 카드 목록은 템플릿 상수에서 생성한다(단일 출처). 별도의 "이어하기" 버튼은 계속 두지 않는다. [확정: 2026-11-25, UX 흐름 재구성]
- AC-01-6: 저장본이 없는 첫 진입(샘플이 손대지 않은 상태)에서 에디터는 시작 화면(S-09)을 연다. 선택지는 이 순서다: ① **내 방 평면도 만들기**(S-03 방 만들기 — 가로·세로 입력 또는 "그려서 만들기"로 S-04 트레이싱) ② **예시 배치로 시작**(템플릿 3종 중 선택, 덮어쓰기 확인 없이 적용) ③ **샘플 방으로 바로 시작**. 닫기(Esc)는 ③과 같다. 저장본을 복원했거나, 저장본 손상 알림이 있거나, 공유·템플릿 링크(`#d=`, `#t=`)로 들어온 경우에는 띄우지 않는다. 손대지 않은 샘플의 가구는 사용자 데이터가 아니므로 평면도를 만들 때(S-03·S-04) "기존 가구 유지/삭제"를 묻지 않고 비운다. [확정: 2026-11-25, UX 흐름 재구성]
- AC-01-2: LocalStorage에 저장본이 있으면 "시작하기"는 샘플 대신 저장본으로 에디터를 연다. 없으면 FR-02 샘플로 연다. (별도의 "이어하기" 버튼은 두지 않는다. 샘플로 돌아가려면 FR-14의 "샘플로 초기화"를 쓴다.)
- AC-01-3: 랜딩은 광고 승인을 위한 **고유 정적 콘텐츠**를 갖는다: ① 사용법 3단계(방 만들기→가구 넣기→간섭 확인) ② 가구 치수 가이드(FR-08 기본 가구 14종의 치수표와 "배치 전에 재야 할 치수" 안내) ③ 자주 묻는 질문 ④ 개인정보처리방침 링크. 콘텐츠는 코드에 포함된 정적 텍스트이며 서버·CMS를 두지 않는다. [확정: 2026-11-18, 애드센스 승인 대응]
- AC-01-4: 개인정보처리방침은 S-01의 하위 정적 페이지로 두고 랜딩 하단과 동의 배너(S-07)에서 연결한다. 광고·제휴·로컬 저장(LocalStorage)·외부 요청 목록(§6)과 "광고로 제3자가 쿠키를 저장하거나 IP 정보를 수집할 수 있음" 고지를 포함한다(애드센스 게시자 정책). 법무 검토는 OPEN-04. [기본값]

### FR-02 기본 원룸 샘플 (S-02)
- AC-02-1: 첫 진입 시 **400×300cm, 천장 230cm** 직사각형 방과 문 1개, 가구 2개 이상이 렌더링된 상태다. [기본값]
- AC-02-2: 샘플은 사용자가 편집·삭제할 수 있다. 샘플 상태에서 사용자가 첫 편집을 하기 전까지는 자동 저장(AC-14-1)이 LocalStorage에 쓰지 않는다.

### FR-03 프리셋 방 생성 (S-03)
- AC-03-1: 프리셋 선택지는 **직사각형**과 **ㄱ자** 두 가지뿐이다. [확정]
- AC-03-2: 직사각형은 가로·세로(cm), ㄱ자는 가로·세로와 잘려나가는 영역의 가로·세로(cm), 공통으로 천장고(cm)를 입력한다. 잘려나가는 영역은 **우상단 모서리**로 고정하고, 회전·반전은 방 생성 후 가구와 무관하게 지원하지 않는다. [기본값]
- AC-03-3: 입력이 정수가 아니거나 범위 밖이면 필드 아래에 오류 문구가 표시되고 "만들기"가 비활성화된다. 범위: 가로·세로 100cm 이상 **방 크기 상한(3000cm) 이하**(OPEN-02 확정), 천장고 180~400cm, ㄱ자 잘림 영역은 가로·세로 각각 전체보다 작고 50cm 이상. [기본값]
- AC-03-4: 확정하면 기존 방이 새 방으로 교체되며 이 동작은 Undo로 되돌릴 수 있다. 교체 전에 기존 가구가 있으면 "가구는 유지/삭제" 중 선택하게 한다. [기본값: 유지, 방 밖이 된 가구는 경고 표시]
- AC-03-5: 프리셋(직사각형·ㄱ자) 아래에 **"홈/돌출 추가"**를 둔다. 벽 번호(미리보기에 번호 표시)·종류(**홈**=안쪽으로 파임, **돌출**=바깥으로 튀어나옴)·위치(벽 시작점에서의 거리)·너비·깊이(cm 정수)를 입력해 "추가"하면 해당 벽 구간에 사각형 홈/돌출이 생기고 미리보기에 즉시 반영된다. 추가는 반복할 수 있고(ㄷ자·T자 등), 벽 번호는 직전 윤곽의 꼭짓점 순서를 따른다(추가 후 번호가 바뀔 수 있음). 기울어진 벽에서는 벽 방향에 수직으로 판다. 벽 목록 직접 입력·사각형 조립은 범위 밖이다. [기본값]
- AC-03-6: 홈/돌출 입력이 아래 범위를 벗어나거나 결과 윤곽이 자기 교차(홈이 맞은편 벽에 닿거나 넘는 경우 포함)하거나 방 크기 상한(3000cm)을 넘으면, 필드 옆 또는 목록 아래에 오류 문구가 표시되고 추가되지 않는다. 범위: 위치 0 이상, 위치+너비 ≤ 벽 길이, 너비·깊이 각각 10cm 이상. **[임의 가정: 최소 10cm는 트레이싱 벽 길이 하한(WALL_MIN)을 그대로 따른 값이며 PRD 확정치가 아님. 위치·너비·깊이 상한은 별도로 두지 않고 벽 길이와 3000cm 상한이 대신한다.]**
- AC-03-7: 추가한 홈/돌출은 "마지막 지우기"와 "초기화"로 되돌릴 수 있다. 직사각형↔ㄱ자 전환 시 추가 항목은 초기화된다. 가로·세로 등 프리셋 값을 바꿔 기존 항목이 더는 맞지 않으면 오류 문구를 보이고 "만들기"를 비활성화한다. 확정은 AC-03-4와 같이 Undo 1단계이며 가구 유지/삭제·방 밖 경고 규칙을 그대로 따른다. 저장 형식은 바뀌지 않는다(결과는 `room.points`). 위·왼쪽으로 돌출하면 방 좌표가 (0,0)으로 재정규화되어 방이 옮겨지므로, 확정 시 "유지"를 고른 가구·고정 요소도 같은 양만큼 옮겨 방 본체 기준 상대 위치를 유지한다(방 밖 개수 안내도 이동 후 좌표 기준). 홈이 벽 시작·끝에 닿으면 그 모서리 꼭짓점이 대체되어 모서리 홈·벽 전체 너비 홈이 만들어진다(AC-03-6 범위 경계 허용). [기본값]

### FR-04 평면도 트레이싱 (S-04)
- AC-04-1: PNG/JPG 이미지를 업로드하면 2D 뷰 배경으로 표시된다. 지원 형식이 아니면 오류 토스트를 표시하고 상태를 바꾸지 않는다.
- AC-04-2: 사용자가 이미지 위의 두 점을 찍고 실제 길이(cm)를 입력하면 **기준선 1개**로 축척이 결정되며, 이후 클릭 좌표가 cm로 변환된다. [확정]
- AC-04-3: 모서리를 순서대로 클릭하면 점이 추가되고, 첫 점을 다시 누르거나 "닫기"를 누르면 다각형이 닫혀 3D 벽체가 생성된다. 점이 3개 미만이면 닫기가 비활성화된다.
- AC-04-4: 선분이 서로 교차하는 다각형은 닫을 수 없고 교차 구간에 오류 표시와 안내 문구를 보여준다.
- AC-04-5: **배경 이미지를 올린 경우** 축척을 설정하기 전에는 모서리 찍기가 비활성화되고 안내 문구를 보여준다. 빈 캔버스(AC-04-7)는 축척이 처음부터 1(cm=cm)로 확정돼 있어 이 제한이 적용되지 않는다.
- AC-04-6: 배경 이미지는 저장 JSON에 포함하지 않는다(용량). 불러오기 후에는 배경 없이 방만 복원된다. [기본값]
- AC-04-7: [그려서 만들기](방 만들기 대화상자의 버튼, 이전 이름 "평면도로 만들기")는 **빈 캔버스**로 시작한다. 격자만 있는 2D 화면에서 이미지·기준선 없이 바로 모서리를 찍을 수 있고 단위는 처음부터 cm다. [확정: 사용자 승인 2026-11-19] 그림 영역은 한 변 3000cm(방 크기 상한) 정사각형이며 영역 밖으로는 점이 찍히지 않고 가장자리로 맞춰진다. [임의 가정: 영역 크기·가장자리 맞춤] 방 추가 세션도 같은 영역이다(AC-23-2: 기존 방은 보이지 않는다). ~~기존 방 경계 상자를 사방 3000cm씩 넓힌 영역(2026-11-23)~~은 FR-23으로 대체됐다. [확정: 사용자 승인 2026-11-26]
- AC-04-8: 빈 캔버스 화면에 **"배경 이미지 올리기(선택)"** 옵션이 있다. 이미지를 올리면 AC-04-1~2·5와 FR-19(윤곽 자동 제안)가 기존대로 동작하며(기준선 단계가 생김) 그 뒤 그리는 방식은 빈 캔버스와 같다. 올리면 이미 찍은 점은 지워진다. 이미지 모드에서 "배경 없이 그리기"를 누르면 확인 후 이미지·점을 지우고 빈 캔버스로 돌아간다. [확정: 합치기는 사용자 승인, 점 초기화·확인창은 기본값]
- AC-04-9: **수평·수직 고정(직각 보정)**을 두며 기본 켜짐이고 토글로 끌 수 있다. 켜짐이면 두 번째 점부터 직전 점 기준으로 커서를 가까운 축(수평/수직)에 투영하며, 그 다음 스냅(켜짐이면 10cm, 꺼짐이면 1cm)을 적용한다(직전 점이 격자 밖이어도 선은 정확히 수평·수직). 끄면 두 축 모두 스냅만 적용한다. [확정: 기본 켜짐·토글은 사용자 승인, 투영→스냅 순서는 기본값]
- AC-04-10: 그리는 중 직전 점에서 커서(보정·스냅 적용 위치)까지 미리보기 선과 길이(cm)를 표시한다. [기본값]

### FR-19 자동 모서리 제안 (S-04) — 브라우저 내 영상처리, AI·API 키 없음
평면도 이미지에서 방 윤곽 모서리를 **제안**한다. 외부 서비스·API 키·서버를 쓰지 않고 브라우저에서 계산한다. 치수 검증이 핵심 가치이므로 실제 길이는 항상 사용자의 기준선 입력과 확인으로 정한다. (AI 분석은 v1.1 후보, §2·OPEN-05)
- AC-19-1: S-04의 ① 이미지 업로드 후 "윤곽 자동 제안" 버튼이 표시된다. 사용하지 않아도 수동 트레이싱(FR-04)은 모든 단계가 그대로 동작한다.
- AC-19-2: 처리는 브라우저 안에서만 한다. 이미지는 어떤 외부 서버로도 전송하지 않는다.
- AC-19-3: 제안 알고리즘은 이미지의 가장 큰 닫힌 윤곽을 찾아 다각형으로 단순화한 모서리 점 목록을 만든다. 구현 방식(순수 JS 또는 영상처리 라이브러리)은 구현 단계에서 정하되, 라이브러리를 추가하면 이유와 번들 크기를 보고한다. [기본값]
- AC-19-4: 처리 전에 이미지를 긴 변 1600px 이하로 축소해 계산하고, 결과 점은 원본 이미지 좌표로 환산한다. [기본값]
- AC-19-5: 결과는 계산이 끝나면(① 직후) 이미지 위에 **점선(미확정) 점**으로 표시한다. 사용자가 기준선으로 축척을 설정(AC-04-2)하고 "적용"을 눌러야 실선 점이 되며, 그 전에는 방을 만들 수 없다. 적용 후에는 점을 드래그해 보정할 수 있다(FR-05).
- AC-19-6: 이미지의 글자(치수 표기)는 읽지 않는다. 축척은 항상 기준선으로 정한다.
- AC-19-7: 결과는 점 3개 이상, 이미지 범위 안, 자기 교차 없음(AC-04-4)을 만족해야 한다. 만족하지 못하거나 윤곽을 찾지 못하면 "윤곽을 읽지 못했습니다. 직접 찍어 보세요" 토스트를 표시하고 기존 트레이싱 상태를 유지한다.
- AC-19-8: 계산은 5초 안에 끝나야 한다. 넘으면 중단하고 AC-19-7과 같은 안내를 표시한다. 계산 중에는 진행 표시와 취소 버튼을 보이고, 화면은 멈추지 않는다. [기본값: 5초]
- AC-19-9: 같은 계산은 동시에 1개만 실행한다. 취소하거나 이미지를 바꾸면 이전 결과를 버린다.

### FR-17 제휴 구매 링크 (S-05) — 수익화
배경·근거는 §11. 사용자가 구매하려는 가구의 치수를 이미 입력한다는 점을 수익 접점으로 쓴다.
- AC-17-1: 기본 가구 14종(FR-08) 중 하나를 선택하거나, **종류를 지정한 치수 박스**(AC-09-6)를 선택하면 속성 패널(S-05)에 "쿠팡에서 {종류} 보기 ↗" 링크가 눈에 띄는 카드(종류 색 블록 아이콘 + 현재 폭 구간 문구)로 표시된다. 상품 사진은 서버·외부 요청이 필요해 쓰지 않는다. 종류가 "기타"인 치수 박스와 고정 요소(FR-06)에는 표시하지 않는다. 카탈로그 가구는 `modelType`, 치수 박스는 `category`가 종류다.
- AC-17-2: 링크는 새 탭으로 열리고, 종류(예: BED)마다 **미리 만들어 둔 쿠팡 파트너스 제휴 URL**로 간다(`rel="sponsored noopener noreferrer"`). URL은 코드 상수의 정적 값이며 앱은 방 구조·배치·치수 등 어떤 사용자 정보도 URL에 담지 않는다. 링크는 종류마다 **치수 구간 3개(소·중·대)**로 나뉘고, 앱은 선택된 가구의 현재 치수가 속한 구간의 URL을 고른다. 구간 선택은 브라우저 안에서만 일어나며 URL에는 치수가 담기지 않는다. [변경: 2026-11-24, 종전은 종류별 고정. 쿠팡에서 종류+치수 검색이 치수에 근사한 결과를 내는 것을 운영자가 직접 확인(침대 등 일부 종류, 표 없이 육안). 쿠팡은 검색 URL을 사람이 변환하는 방식이라 즉석 생성 불가]
- AC-17-3: 링크 바로 옆에 "제휴 링크입니다. 구매 시 수수료를 받을 수 있습니다" 문구를 항상 함께 표시한다. 문구 없이 링크만 노출하는 상태는 허용하지 않는다.
- AC-17-4: 링크는 어떤 기능도 막거나 선행 조건으로 요구하지 않는다. 링크 클릭 여부와 관계없이 편집·저장·내보내기는 동일하게 동작한다.
- AC-17-5: 제휴 링크 설정은 종류별 구간 URL 맵 1개를 코드 상수 한 곳에서 관리한다. 구간 경계 치수와 구간별 URL을 함께 둔다. 현재 치수가 속한 구간의 URL이 없으면 같은 종류의 다른 구간으로 대체하지 않고 링크를 표시하지 않으며, 전체가 비어 있으면 기능이 숨겨진다. 구간별 검색어(예: 침대 폭 110cm)와 변환 방법은 운영 메모로 남긴다. 구간 기준이 되는 축(W/D)은 종류별로 운영자가 정한다. [기본값]
- AC-17-6: 링크 URL은 운영자가 쿠팡 파트너스 [간편 링크 만들기]로 종류·구간별 검색 결과 URL을 변환해 상수에 넣는 사전 작업의 결과다(상품 DB 불필요). 작업이 끝난 구간부터 AC-17-5에 따라 링크가 나타난다. 출시 전 14종×3구간=42개를 모두 채우는 것이 목표이나 미완 구간이 있어도 출시는 막지 않는다(해당 구간만 링크 숨김). [기본값]

### FR-18 비침습형 광고 (S-01, S-06 동의 토글, S-07) — 수익화
- AC-18-1: 광고 노출 위치는 **랜딩(S-01) 콘텐츠 영역 안 1칸**뿐이다. 광고 수는 콘텐츠보다 적어야 한다. [확정: 2026-11-18, 애드센스 정책(도구 화면·콘텐츠 없는 화면 광고 금지) 대응으로 메뉴 시트 광고 삭제]
- AC-18-2: 랜딩은 에디터와 별도 문서(별도 페이지 로드)이다. 에디터 문서(S-02~S-07)에는 광고를 표시하지 않으며 광고 스크립트도 로드하지 않는다.
- AC-18-3: 전면·팝업·자동 재생 영상·화면 이동 유도 광고를 사용하지 않는다.
- AC-18-4: 광고 영역은 크기를 미리 예약해 광고 로드 전후로 레이아웃이 밀리지 않는다(레이아웃 이동 없음). 광고가 로드되지 않거나 차단돼도 빈 영역 대신 영역이 접히고 기능에 영향이 없다.
- AC-18-5: 광고 스크립트는 사용자가 개인정보·쿠키 동의 배너(S-07)에서 허용한 뒤에만 로드한다. 거부 또는 미응답 상태에서는 어떤 광고 요청도 보내지 않고 광고 영역을 접는다.
- AC-18-6: 동의 선택은 LocalStorage에 저장되며, 메뉴(S-06)에서 언제든 바꿀 수 있다.
- AC-18-7: 광고 설정(네트워크 ID, 슬롯 ID)은 코드 상수 한 곳에서 관리하고, 값이 비어 있으면 광고 영역, 동의 배너, 메뉴(S-06)의 동의 토글을 모두 표시하지 않는다.

### FR-20 PWA (오프라인·설치) (S-02, S-06)
무가입·무설치 가치를 해치지 않는 선택 기능이다. 설치하지 않아도 모든 기능이 그대로 동작한다. [확정: 2026-11-24]
- AC-20-1: 웹 앱 매니페스트를 제공한다. `name` "RoomFit 3D", `short_name` "RoomFit", `display` `standalone`, `start_url` `/editor.html`, `scope` `/`, `lang` `ko`, 색상은 DESIGN.md 값이다(`theme_color` `#0f2a4a`, `background_color` `#eaf0f6`). 아이콘은 192px, 512px, 512px maskable을 둔다. 랜딩·에디터·방침 HTML 모두 매니페스트와 `theme-color`를 연결한다.
- AC-20-2: service worker는 **프로덕션 빌드에서만** 등록한다. 빌드 해시가 붙은 HTML·JS·CSS는 프리캐시하고, 폰트(woff2)는 사용된 파일만 런타임 캐시한다(92개 전체를 프리캐시하지 않음). 교차 출처 요청(광고, 제휴 링크 이동)은 service worker가 가로채지도 캐시하지도 않는다. 페이지는 SPA 폴백 없이 각 HTML 문서 그대로 서빙한다.
- AC-20-3: 한 번 열어 본 뒤에는 오프라인에서도 랜딩·에디터·방침이 열리고, 편집·자동 저장·JSON 저장/불러오기·캡처가 동작한다. 오프라인에서 광고와 제휴 링크가 동작하지 않아도 레이아웃은 깨지지 않는다(AC-18-4).
- AC-20-4: **자동 업데이트**한다. 새 버전의 service worker는 안내 UI 없이 설치·활성화된다. 편집 중인 페이지를 강제로 새로고침하지 않으며, 새 번들은 다음 페이지 로드부터 적용된다. 자동 저장 데이터는 업데이트로 변하지 않는다.
- AC-20-5: **설치 안내**는 메뉴(S-06)의 "앱으로 설치" 항목 하나로 한다. Chromium 계열은 `beforeinstallprompt`를 보관했다가 항목을 눌렀을 때만 설치 프롬프트를 띄운다. iOS처럼 프롬프트 API가 없는 환경은 같은 항목이 "공유 → 홈 화면에 추가" 안내를 모달로 보여 준다. 이미 설치되어 실행 중(standalone)이거나 설치할 수 없는 환경에서는 항목을 숨긴다. 자동 팝업·상단 배너·반복 안내는 두지 않는다.
- AC-20-6: 에디터 시작 시 `navigator.storage.persist()`를 지원하면 한 번 요청한다. 거부·미지원·오류는 조용히 무시하고 어떤 안내도 띄우지 않는다. [기본값]
- AC-20-7: 개인정보처리방침에 "오프라인 사용을 위해 앱 파일을 브라우저에 저장(캐시)한다"는 한 줄을 추가한다. 외부로 나가는 요청 목록(§6)은 달라지지 않는다.

### FR-22 메뉴·공유 구성 (S-02, S-06) [확정: 2026-11-25, UX 흐름 재구성]
- AC-22-1: 사용 흐름은 시작(랜딩의 시작하기·예시 배치 → 에디터 시작 화면 S-09, AC-01-6) → 편집(S-02) → 마무리(공유) 순이다. 작업의 결과를 내보내는 동작(공유 링크·캡처)은 상단 바 "공유" 버튼 하나에 모으고, 메뉴(S-06)에는 두지 않는다.
- AC-22-2: 메뉴(S-06)는 저장 상태 줄 아래에 목적별 그룹으로 묶는다: **시작**(템플릿 불러오기, 샘플로 초기화, 배치 가이드[새 탭]), **파일**(JSON 내보내기, JSON 불러오기), **앱**(앱으로 설치, 설치 가능할 때만), 마지막에 광고·쿠키 동의(AC-18-6, 설정이 있을 때만).

### FR-21 평형별 템플릿·배치 가이드 (S-01, S-06, S-08) [확정: 2026-11-25, 사업성 검토 §5-3·§5-4]
- AC-21-1: 템플릿은 코드 상수 3종(원룸 약 5평 330×500, 침실 약 4평 300×420, 거실 약 7평 450×520, 천장 230)이며 모두 저장 스키마 검증을 통과하고 간섭 경고가 없다.
- AC-21-2: 메뉴(S-06) "시작" 그룹의 "템플릿 불러오기"는 목록에서 고르면 덮어쓰기 확인 대화상자(AC-14-4)를 거쳐 문서를 교체한다. Undo로 되돌릴 수 있다.
- AC-21-3: 정적 페이지 `/guide.html`(S-08)은 공통 배치 원칙과 템플릿별 배치 설명을 담고, 템플릿마다 `/editor.html#t=<id>`로 여는 링크를 둔다. 해시 진입은 AC-14-8과 같은 확인 흐름을 쓴다. 알 수 없는 id는 무시한다. 랜딩 헤더·푸터와 에디터 메뉴(S-06) "시작" 그룹(새 탭)에 가이드 링크를 둔다. 광고는 두지 않는다(AC-18-1).

### FR-23 방 단위 그리기와 배치 (S-10, S-04) [확정: 2026-11-26, 사용자 승인. 구현: 1~3단계]
배경: 전체 평면도를 한 번에 정확히 그리기 어렵다. 방 하나씩 모양만 그리고, 배치는 별도 화면에서 이어 붙인다. 평면도 이미지 모드(AC-04-8)는 이미지 위에서 위치가 정해지므로 지금 방식을 유지한다(결정: 2026-11-25).
- AC-23-1: **방 종류**는 안방·거실·주방·옷방·욕실·작은방·현관·베란다 8개 기본 칩과 [직접 입력]이다. 직접 입력한 종류는 방에 저장되고(별도 목록 없음) 이후 칩 줄에 같이 나온다. 종류는 최대 20자 문자열이며 방 이름의 기본값이 된다. 같은 이름이 이미 있으면 "작은방 2"처럼 번호를 붙인다. 이름은 나중에 바꿀 수 있다.

- AC-23-4: S-10에서 방을 끌어 옮길 수 있다. 끄는 방은 다른 방의 변·꼭짓점에 가까우면(15cm 이내, AC-04-15와 같은 반경) 달라붙는다. 내부가 겹치면 놓을 수 없고 붉게 표시되며 직전 위치로 돌아간다. 집 전체 크기 10000cm 초과도 같다(AC-04-16).

## 6. 비기능 요구사항
- 성능: 가구 30개 기준 데스크톱 60fps 목표, 모바일 30fps 이상 [기본값].
- 접근성: 모든 버튼에 텍스트 또는 `aria-label`, 포커스 표시, 경고는 색상 외에 아이콘/텍스트로도 표시(색약 고려). 토스트는 오류·경고(문구가 ⚠로 시작)면 `role="alert"`, 그 외는 `role="status"`이며, 폼 필드 오류는 `aria-describedby`로 연결하고 `alert`를 쓰지 않는다. (구현에 맞춰 추가(2026-11-19))
- 브라우저: 최신 Chrome/Edge/Safari/Firefox. WebGL 미지원 시 랜딩은 안내 문구를 표시하고, 에디터는 캔버스 영역을 "이 브라우저는 3D를 지원하지 않습니다. 최신 Chrome/Edge/Safari/Firefox를 사용하세요." 안내로 대체한다(패널 편집·자동 저장은 그대로 동작) [기본값]. 3D 컨텍스트가 소실되면 캔버스를 "화면을 다시 불러오는 중…" 오버레이로 덮고, 5초 안에 복구되지 않으면 [새로고침] 버튼을 표시한다 [기본값]. (구현에 맞춰 수정(2026-11-19))
- 배포: 루트 도메인에 배포한다(하위 경로 배포 아님). [확정: 2026-11-19]
- 개인정보: 방·가구 데이터는 서버로 전송하지 않고 브라우저 로컬에만 저장한다. 공유 링크(AC-14-7)는 사용자가 복사해 전달할 때만 이동하며 해시라 서버에 전송되지 않는다. 외부로 나가는 요청은 (a) 동의한 경우의 광고 요청(랜딩, FR-18), (b) 사용자가 제휴 링크를 눌렀을 때 쿠팡 파트너스 페이지가 열리는 요청(종류·구간별 정적 URL, 방·가구·치수 정보 미포함, FR-17)뿐이다. 오프라인 사용을 위해 앱 파일(HTML·JS·CSS·폰트)을 브라우저 캐시에 저장하며 사용자 데이터는 포함하지 않는다(FR-20). 평면도 이미지는 브라우저 밖으로 나가지 않는다(FR-19).
- 운영 비용: 정적 호스팅만 사용하고 자체 서버·DB·로그인을 두지 않는다. 수익 측정은 제휴·광고 네트워크의 대시보드를 쓰며 자체 분석 도구를 만들지 않는다.

## 11. 수익화

### 11.1 전제와 제약
- 핵심 가치는 **무가입·무설치·낮은 입력 피로도**(기획서 §1)다. 수익 모델은 이 가치를 깨지 않아야 한다.
- 서버 없이 정적 호스팅으로 운영하므로 고정 운영비가 매우 낮다. 따라서 목표는 큰 수익이 아니라 **운영비(호스팅·도메인·도구 비용)를 넘는 최소 수익 확보**다.
- 수익을 **보장**할 수는 없다. 이 문서는 수익이 발생할 구조와 손익분기 판단 기준을 정의할 뿐이며, 실제 금액은 트래픽과 제휴·광고 단가에 달려 있다.

### 11.2 검토한 방안과 결정

| 방안 | 결정 | 이유 |
| --- | --- | --- |
| 제휴 구매 링크 | **채택(FR-17)** | 가구를 배치해 보며 구매를 고민하는 맥락이라 구매 의도가 높은 접점이다. 링크는 종류별 3개 치수 구간으로 나뉘며(AC-17-2), 치수 박스는 사용자가 종류를 지정한 경우에만 표시한다(AC-09-6). 가입·서버 불필요, 구현은 종류·구간별 URL 상수 |
| 비침습형 광고 | **채택(FR-18)** | 가입 불필요. 단, 편집 경험과 애드센스 정책을 지키기 위해 랜딩에만 노출 |
| Pro 유료 플랜(클라우드 저장·동기화·다중 프로젝트) | 제외 | 계정·결제가 필요해 "무가입" 가치와 충돌하고 기획서상 v2.0(클라우드 계정) 범위. 무료 이용자 규모가 확인된 뒤 재검토 |
| B2B/파트너 제휴(브랜드·이사·인테리어 임베드/리드) | 제외 | 영업이 필요하고 초기 수익이 불확실. 브랜드 가구 DB(v2.0)와 함께 재검토 |

### 11.3 수익 구조

수익은 두 갈래다.

1. **제휴 수수료** = 제휴 링크 클릭 수 × 구매 전환율 × 평균 구매액 × 수수료율
2. **광고 수익** = 광고 노출 수 × 노출당 단가(또는 클릭 수 × 클릭당 단가)

가구는 단가가 높은 품목이라 같은 클릭이라도 건당 수수료가 큰 편이다. 반대로 구매 전환은 방 배치 후 수일~수주 뒤에 일어날 수 있어 초기에 수익이 눈에 보이기까지 시간이 걸린다.

### 11.4 손익분기 판단 기준
- 월 고정 운영비 = 호스팅 + 도메인 + 기타 도구 비용(자체 서버 없음). 실제 값은 선정 후 기입한다.
- 손익분기 조건: `제휴 수수료 + 광고 수익 ≥ 월 고정 운영비`.
- 측정은 제휴·광고 네트워크 대시보드의 월 클릭·전환·노출·수익으로 하고(§6), 자체 분석 도구는 만들지 않는다.
- 임계치와 목표 금액은 OPEN-04 확정과 운영 데이터(쿠팡 수수료 기본 3%, 광고 단가)가 쌓인 뒤 정한다. 지금 수치를 가정해 적지 않는다.

### 11.5 위험과 완화

| 위험 | 완화 |
| --- | --- |
| 광고가 편집 경험·성능을 해침 | 편집 영역 광고 금지(AC-18-2), 영역 크기 예약(AC-18-4), 팝업·전면 광고 금지(AC-18-3) |
| 제휴 링크가 광고성임을 숨김 | 항상 고지 문구 표시(AC-17-3), `rel="sponsored"` |
| 개인정보·쿠키 규제 | 동의 후에만 광고 로드(AC-18-5), 방 데이터는 외부로 보내지 않음(§6), 법무 검토는 OPEN-04 |
| 제휴 약관·심사 미충족 | 운영자 준비 단계(쿠팡 파트너스 가입·정산 조건 확인)에서 확인하고, 미충족이면 설정을 비워 링크를 숨김(AC-17-5) |

### 11.6 재검토 시점
- 월 방문자와 제휴 클릭 데이터가 쌓인 뒤 §11.4 손익분기를 점검한다.
- 손익분기에 못 미치고 사용자 요구가 확인되면 Pro 플랜·브랜드 가구 DB 제휴를 별도 PRD로 검토한다.
