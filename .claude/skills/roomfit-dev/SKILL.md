# RoomFit 3D 개발 오케스트레이터

**실행 모드:** 서브에이전트 위임, 순차 실행(구현 → 검증). 1인 개발이라 기능 하나씩 작게 끝내는 것이 목표다.

## 0. 맥락 확인
- `docs/기획서.md`의 6장 순서(PoC → 상태 관리 → UI)와 현재 코드 상태를 확인해 요청이 어느 단계인지 정한다.
- 프로젝트가 아직 스캐폴딩 전이면 먼저 Vite React-TS 프로젝트를 만든다. 이 작업은 직접 처리한다.
- 후속 요청이면 `_workspace/`의 직전 QA 보고서를 읽고 지적된 부분만 해당 에이전트에게 다시 맡긴다.

## 1. 구현
기능을 영역별로 나눠 위임한다. 에이전트는 먼저 `roomfit-conventions`를 읽는다.

| 영역 | 에이전트 |
| --- | --- |
| 3D 렌더링, 드래그·스냅, 충돌, 카메라 | `scene-engineer` |
| 스토어, Undo/Redo, JSON·LocalStorage, UI 패널 | `app-engineer` |

- 두 영역이 서로 의존하면 인터페이스(스토어 타입)를 `app-engineer`가 먼저 정하고 `scene-engineer`가 이어받는 순서로 직렬 실행한다. 독립적이면 병렬로 호출한다.
- 기능 하나가 끝나면 다음 기능으로 넘어가기 전에 검증한다. 전체를 모아서 한 번에 검증하지 않는다.

## 2. 검증
`qa-reviewer`를 호출해 빌드·테스트 결과와 경계 대조 보고서를 받는다. 보고서는 `_workspace/{기능}_qa.md`로 저장한다.
- 차단 항목이 있으면 해당 에이전트에게 지적 내용만 넘겨 고치게 하고 다시 검증한다. 최대 2회 반복하고 그래도 남으면 사용자에게 보고한다.

## 3. 마무리
변경 내용, 검증 결과, 남은 위험을 간단히 보고한다. 커밋은 사용자가 요청할 때만 한다.

## 오류 처리
- 에이전트 실패는 1회 재시도한다. 한도 소진·권한 거부처럼 재시도해도 같은 실패는 재시도하지 않고 보고한다.
- 기획서와 충돌하거나 스키마 변경이 필요한 요구는 임의로 처리하지 않고 사용자에게 확인한다.

## 테스트 시나리오
- **정상:** "직사각형 방을 만들고 가구를 10cm 스냅으로 드래그하게 해줘" → app-engineer가 room 스토어, scene-engineer가 방·드래그 구현 → qa-reviewer가 빌드와 스냅 규칙 확인 → 통과 보고.
- **오류:** QA가 "JSON 불러오기 검증 누락"을 차단으로 지적 → app-engineer에게 해당 항목만 재위임 → 재검증 → 2회 후에도 실패하면 사용자에게 보고.
